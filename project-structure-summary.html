qData Repository Map

qData 项目结构总览

这份页面把仓库拆成“后端聚合、业务模块、公共底座、前端工程、独立子服务、部署资源”几层， 方便你在改功能、查入口、找模块时快速定位。

Maven 多模块 Spring Boot 后端 Vue 3 前端 ETL / 质量 / AI 独立能力 Docker + SQL 初始化

仓库骨架

D:\qData-develop
├─ qdata-framework/      公共基础设施层
├─ qdata-module-*/       业务域模块层
├─ qdata-server/         后端启动入口
├─ qdata-ui/             Vue 3 前端
├─ qdata-etl/            ETL 引擎/工具
├─ qdata-quality/        数据质量能力
├─ qdata-api-ds/         API / 调度相关能力
├─ qdata-ai/             AI 服务
├─ sql/                  初始化与升级脚本
├─ docker/               容器化部署配置
├─ docs/                 文档
└─ datax/                DataX 相关资源

如果你只想先摸清项目脉络，建议从 qdata-server、qdata-framework 和 qdata-ui 三块开始。

关键入口

后端根 pom /pom.xml
后端启动类 qdata-server / QDataApplication.java
前端入口 qdata-ui / src / main.js
前端路由 qdata-ui / src / router / index.js

后端是 Spring Boot 启动壳，前端是 Vite + Vue 3 工程，两个入口最值得先记住。

后端分层

层级 目录 / 模块 说明
公共底座 qdata-framework 放通用能力：配置、安全、缓存、定时任务、文件、MyBatis、公共工具等。
业务模块 qdata-module-system / att / da / dp / dpp / ds / dm / mc / dg / ai 按业务域拆分，每个模块通常再分 api 和 biz，便于独立开发与复用。
统一启动 qdata-server 真正的后端运行入口，负责把各业务模块拼装成一个服务。
独立能力 qdata-etl / qdata-quality / qdata-api-ds / qdata-ai 这些更像独立子工程，负责 ETL、质量校验、API 调度、AI 能力等。

前端结构

qdata-ui / src 的核心目录
  • api：接口封装
  • assets：静态资源
  • components：通用组件
  • composables：组合式逻辑
  • directive：自定义指令
  • i18n / locales：多语言
  • layout：整体布局
  • plugins：插件
  • router：路由
  • store：状态管理
  • utils：工具函数
  • views：页面
views 里常见的业务域
  • sys：系统管理、登录、权限、菜单、监控等
  • da：数据资产、数据源、质量、查询等
  • dpp：集成/任务相关页面
  • mc：元数据相关页面
  • att：标签、规则、主题等
  • dm：数据建模
  • ai：AI 相关页面

快速导航

改后端功能时先看哪里
  • 先找对应的 `qdata-module-*`
  • 再看 `biz` 包里的 controller / service / mapper
  • 公共依赖一般回到 `qdata-framework`
改前端页面时先看哪里
  • 先找 `qdata-ui/src/views/...`
  • 路由在 `src/router/index.js`
  • 共享逻辑常在 `src/utils` 或 `src/store`
部署相关先看哪里
  • `sql/`：初始化和升级脚本
  • `docker/`：容器化配置
  • `docs/`：部署说明
  • `datax/`：DataX 相关脚本

一句话总结

这个仓库的主线很清晰：`qdata-framework` 提供底座，`qdata-module-*` 承载业务，`qdata-server` 负责启动装配，`qdata-ui` 负责页面呈现，`qdata-etl / qdata-quality / qdata-ai` 负责专项能力。 如果你下一步要深入某个功能，先按“业务域”定位，再向下找 controller、service、mapper 或 Vue 页面，效率最高。
