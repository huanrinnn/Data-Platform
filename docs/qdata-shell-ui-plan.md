# qData 全项目新壳迁移计划

## 1. 范围

本计划针对整个 qData 项目套壳，不限于当前新壳已实现的工作台、资产、数据源和 ETL 页面。

迁移对象包括：

- 旧前端 `qdata-ui` 的全部页面、路由、权限菜单、请求封装、上传下载、国际化和 WebSocket。
- `qdata-server` 主业务服务全部接口。
- `qdata-ai` 独立 AI 服务接口。
- `qdata-quality` 独立质量服务接口。
- 系统管理、数据资产、数据开发、数据治理、数据标准、数据模型、元数据、数据服务、标签、AI、质量、报表和扩展模块。

## 4. 新旧壳隔离

1. 旧壳入口 `/`、开发端口 `81`、构建配置和运行行为保持不变。
2. 新壳入口 `/shell/`、开发端口 `82`、环境变量、路由、资源和构建目录独立。
3. 新壳只适配既有后端接口，不修改接口路径和后端业务逻辑。
4. 迁移期间旧壳继续作为完整功能入口，新壳按阶段并行验证。
5. 新壳主服务、AI 服务、质量服务使用独立 Base URL：
   - 主服务：`/dev-api`、`/prod-api`
   - AI 服务：`/dev-ai`、`/prod-ai`
   - 质量服务：`/dev-quality`、`/prod-quality`
6. Token、Cookie、Storage key、登出和 401 跳转必须显式处理，避免两个壳互相清理状态。
7. 不覆盖用户当前已有的旧壳、后端和数据库未提交修改。
8. 最终切换通过反向代理入口切换完成，保留旧壳回滚入口。

## 6. 接口适配标准

### 主服务

- Base URL 为 `/dev-api` 或 `/prod-api`。
- 默认发送 `Authorization: Bearer <Admin-Token>`。
- 登录、验证码等公共接口显式设置 `isToken: false`。
- GET 参数使用 Axios `params`，禁止手工拼接未编码参数。
- PUT/DELETE 是否转 POST 由独立环境变量控制，并设置 `X-HTTP-Method-Override`。

### AI 服务

- 使用独立 Axios/SSE 客户端。
- `/chat/message/send-stream` 等流式接口使用 SSE 客户端，不进入普通 JSON 响应拦截器。
- 支持取消、异常中断、重试和会话切换。

### 质量服务

- 使用独立质量服务 Base URL。
- 分页、异常数据、校验 SQL 和执行结果使用独立适配器。
- 质量服务错误不应触发主服务全局登出，除非明确返回认证失效。

### 返回格式

请求层必须兼容：

- `CommonResult<T>`：`{ code, data, msg }`
- `AjaxResult`：`{ code, msg, data, ...业务字段 }`
- 分页：`data.rows`、`data.total`
- 数组、树、对象、Blob/ArrayBuffer 和 SSE
- HTTP 2xx 但业务 `code != 200` 的失败响应

## 7. 执行阶段

### P0：公共层和隔离

1. 固化 `/shell/`、端口 `82` 和独立环境变量。
2. 建立主服务、AI、质量三个请求客户端。
3. 迁移登录、验证码、登出、用户信息、Token、401、错误码和权限基础。
4. 迁移上传下载、文件流、重复提交校验、请求取消、语言头和路由刷新。
5. 建立新壳动态路由、菜单、权限指令和页面缓存基础设施。

验收：旧壳 `/` 不受影响；新壳可登录；401、文件流、SSE、刷新深链接均正确。

### P1：系统与框架

按接口清单逐条迁移 `system` 162 个接口和三个 framework 模块 30 个接口，完成系统管理全部页面与权限菜单。

验收：用户、角色、部门、菜单、字典、配置、通知、消息、日志、监控、代码生成、定时任务闭环可用。

### P2：资产、开发、服务

按接口清单逐条迁移 `da` 214 个、`dpp` 138 个、`ds` 24 个接口，优先完成列表、详情、保存、修改、删除、状态、导入导出，再完成预览、血缘、节点编排、实例日志和服务测试。

验收：资产、数据源、开发任务、集成任务、API 服务和运行实例全流程可用。

### P3：治理、标准、模型、元数据

按接口清单逐条迁移 `dg` 76 个、`dp` 77 个、`dm` 44 个、`mc` 100 个、`att` 174 个接口。

验收：树目录、分页、详情、关联关系、批量操作、导入导出和跨模块选择器可用。

### P4：质量、AI、报表和遗留扩展

按接口清单逐条迁移质量 8 个、AI 独立服务 12 个、主服务 AI 18 个，以及 `report`、`rp`、`example` 和剩余接口。

验收：质量执行、异常处理、AI 流式问答、模型选择、报表、个人中心和扩展功能可用。

## 8. 每个接口的逐条实施记录

基于 `api-inventory.csv` 生成迁移矩阵，每条接口必须增加以下字段：

| 字段 | 内容 |
|---|---|
| `service` | 服务 |
| `module` | 模块 |
| `method` | HTTP 方法 |
| `path` | 完整路径 |
| `frontendApiFile` | 新壳 API 文件 |
| `frontendPage` | 调用页面或组件 |
| `requestShape` | query/path/json/form-data/blob/SSE |
| `responseShape` | page/list/tree/object/blob/SSE |
| `authRequired` | 是否需要 Token |
| `status` | 未迁移/已封装/已接入/已验证/后端废弃 |
| `verification` | 验证方式和结果 |

单条接口完成标准：API 封装、页面调用、成功返回、业务失败、401、空数据、重复提交、文件流/SSE（若适用）和浏览器 Network 验证全部完成。

## 9. 验证门禁

每个阶段必须执行：

1. `qdata-shell-ui`: `npm run build`
2. 静态检查。
3. 新壳请求路径与 `api-inventory.csv` 对比。
4. 页面 CRUD、分页、搜索、详情、导入导出和异常场景验证。
5. `git diff --name-only` 检查，确认旧壳和后端没有被意外修改。
6. 保留旧壳构建和入口回归记录。

整体交付门禁：

- 1,080 个接口全部有迁移状态。
- 旧壳全部可见菜单都有新壳路由或明确结论。
- 新旧壳可以同时构建、部署和回滚。
- `/shell/` 深链接刷新不返回 404。
- 主服务、AI 服务、质量服务生产代理路径均已验证。
